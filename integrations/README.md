# Tier 3 adapters

Tier 3 hosts have their own plugin systems but uncertain or limited
instruction-injection semantics. Qoder and Grok Build ship real manifests in
this repo (layouts verified by [ponytail](https://github.com/DietrichGebert/ponytail));
the rest register via the shared `skills/` + rules + MCP surface. Everything
shares the same memory store — set `MEMVAULT_AGENT_ID` per host.

## Qoder (closest to full tier 1)

- Rules: `.qoder/rules/memvault.md` is read per-project (canonical copy,
  regenerated by `scripts/gen-rule-copies.sh`). `AGENTS.md` also works.
- Manifest: `.qoder-plugin/plugin.json` (skills under `plugins/memvault/skills/`).
- MCP: register `memvault-mcp --transport stdio` in Qoder's MCP settings;
  identity `MEMVAULT_AGENT_ID=qoder` (see `mcp-clients/`).
- Hooks: Qoder's `UserPromptSubmit` hook is already shipped — see
  "Qoder prompt hook" below (`plugins/memvault/hooks/qoder-hooks.json` +
  `qoder-prompt.sh`). No *other* tier-3 host has an equivalent hook file yet,
  so recall there stays rules-driven until batch 3.

## Grok Build

```
grok plugin install dreamor/memvault --trust
```

Reads the root `plugin.json` (its `mcpServers` block registers
`memvault-mcp --transport stdio`) + `.grok-plugin/marketplace.json`; skills
and commands directories are resolved by manifest paths. Passive hook output
cannot inject instructions on Grok, so recall is rules-driven: point Grok at
`AGENTS.md` (repo root) or paste `integrations/rules/agents-snippet.md`.

## pi / Hermes / OpenClaw / Swival / Devin

| Host | How |
|---|---|
| **pi** | `pi install git:github.com/dreamor/memvault` — the root `package.json` `pi` manifest loads [`pi-extension/`](../pi-extension/) (`before_agent_start` recall injected as a CustomMessage). |
| **Hermes** | [`hermes/`](hermes/) Python plugin (REST-only, stdlib): `pre_llm_call` recall once per session ✅. `extract_session()` ships but is **not** wired to any host event yet — call it manually or wire it once Hermes' session-end hook name is confirmed (see `hermes/README.md`). |
| **OpenClaw** | repo-root `.openclaw/skills/` is generated by `scripts/gen-rule-copies.sh` (byte-copy of the plugin skills); ClawHub publishing (`clawhub publish`) is a manual step once verified. |
| **Swival** | `swival skills add https://github.com/dreamor/memvault` picks up the generated repo-root `skills/` (or stage into `~/.config/swival/library`). |
| **Devin** | Settings knowledge: paste `integrations/rules/agents-snippet.md`; run MemVault in HTTP mode (`memvault-mcp --transport http`) and register the MCP URL. |

### Qoder prompt hook

`plugins/memvault/hooks/qoder-hooks.json` templates a `UserPromptSubmit`
hook that recalls memories on the first prompt of each session
(`qoder-prompt.sh` dedups per session_id, REST-only). Verify that Qoder
treats plain stdout as prompt context; the hook fails closed (exit 0, no
output) on any backend error.
